# Pull Client Docs

Populate a client repo with the full content of their **intake form** and **strategy/meeting call transcript** Google Docs, replacing the placeholder link stubs, then commit and push.

## Inputs

- **Client / repo name** (e.g. `David_Dewey`). If the user didn't say which client, ask or infer from the current directory. The repo lives at `<LGJ Clients>/<ClientName>/`.

## Steps

### 1. Locate the source Google Doc IDs

The freshly cloned repo already contains two placeholder stub files that link to the source Docs:

- `intake-form.md` — contains the intake Doc URL/ID
- `strategy-call-transcript.md` — contains the strategy/meeting call Doc URL/ID

Read both files and extract the Google Doc IDs from the URLs (the long ID in `docs.google.com/document/d/<ID>/edit`).

**Fallback** — if a stub is missing or has no ID, search Drive by the naming convention used for LGJ buildouts:
- Intake: `Custom Buildout Intake x <Client Name>`
- Transcript: `Custom Buildout Strategy x <Client Name>` (or `... Transcript ...`, `Kickoff call transcript`, `strategy call transcript`)

Use `mcp__claude_ai_bridgekit__search_drive_files` with `file_type: "document"` and confirm the match is the correct client before reading.

### 2. Read the Docs

Call `mcp__claude_ai_bridgekit__read_google_doc` with each Doc ID (both can be done in parallel). This returns the title and plain-text content.

### 3. Write clean Markdown

Overwrite the two stub files with full Markdown:

- **intake-form.md** — Lead with `# <Doc Title>` and a `**Source:** [Google Doc](<url>)` line. Structure the intake into readable sections (Contact Details, what they do, case studies, customer avatar, industries to target, job titles, USP, lead magnets, service area, internal research notes). Use headings, bullet lists, and bold field labels. Preserve all content — don't summarize or drop the internal research/notes section.
- **strategy-call-transcript.md** — Lead with `# <Doc Title>` and a metadata block (meeting date, duration, attendees, emails, Fathom share/recording URLs). Then render the transcript with each turn as `**HH:MM:SS — Speaker**` followed by their text on the next line. Clean up obvious transcription artifacts/garbled fragments lightly for readability, but do not invent or remove substance.

Keep the existing footer line if present (e.g. `*Generated by HTM Portal on <date>*`).

### 4. Commit and push

```bash
cd "<LGJ Clients>/<ClientName>"
git add intake-form.md strategy-call-transcript.md
git commit -m "Add full intake form and strategy call transcript content

Pull the <Client> intake form and strategy call transcript from Google
Drive into the repo as full Markdown, replacing the placeholder stubs."
git push origin HEAD
```

If `git push` fails with `could not read Username for 'https://github.com'`, the HTTPS remote has no credential helper. Fix it with `gh auth setup-git` then push again (the repos were cloned via the `gh` CLI, which is authenticated).

End commit messages with the required Co-Authored-By trailer.

## Notes

- If git has no global identity, commits will be attributed to the machine default. Mention this to the user and offer to set `user.name`/`user.email` — don't set it silently.
- Confirm the Drive doc actually belongs to the named client before overwriting repo files; intake/strategy docs for many clients share the same title prefix.
- Do all independent reads (both Docs, both stub files) in parallel.
